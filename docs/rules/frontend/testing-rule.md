# Frontend Testing Rule

## 1. 문서 목적

이 문서는 React 프론트엔드의 테스트 코드 작성 범위와 코드 테스트로 남기지 않는 영역의 검증 방식을 정의한다.
목표는 전체 커버리지가 아니라, 회귀가 발생했을 때 빠르게 잡아낼 수 있는 핵심 로직을 선별해 테스트하는 것이다.

---

## 2. 기본 원칙

- 프론트엔드 코드는 전체를 테스트 코드로 덮지 않는다. **핵심 로직(계산, 분기, 데이터 변환)만 선별적으로 테스트한다.**
- 단순 렌더링·레이아웃·조합 위주의 코드는 테스트 코드 대신 `docs/qa/` 시나리오 문서 + Playwright MCP 수동 확인으로 검증한다.
- 테스트는 구현 세부가 아니라 관찰 가능한 동작(입력 → 출력, 렌더링 결과)을 검증한다.

---

## 3. 테스트 도구

| 용도 | 도구 |
|---|---|
| 단위/컴포넌트 테스트 | Vitest + React Testing Library |
| 골든 패스 / 에러 상태 확인 | Playwright MCP (자동화된 CI 테스트가 아니라 자체점검 시 에이전트가 브라우저를 직접 조작해 확인) |

Playwright MCP 확인 결과는 코드로 남기지 않고 `docs/qa/` 시나리오 문서로 남긴다 (4장 참고).
자동화된 E2E 테스트 스위트(`@playwright/test` 등)는 이 문서의 범위가 아니다. 필요해지면 별도 Rule로 다룬다.

---

## 4. 단위/컴포넌트 테스트 작성 기준

### 4-1. 테스트를 작성하는 대상

다음 중 하나라도 해당하면 Vitest 테스트를 작성한다.

- `src/lib`, `src/utils` 등에 있는 순수 함수 중 분기나 계산이 있는 것 (예: 적합도 점수 → 색상/등급 매핑, 날짜/금액 포맷팅)
- axios interceptor의 에러 메시지 우선순위 로직처럼, 입력에 따라 다른 결과를 반환하는 로직 (frontend-rule.md §4-2)
- 폼 검증 로직 (필수값, 형식 검증 등 커스텀 validator)
- 커스텀 훅 내부에 있는 계산/분기 로직 (단, React Query의 단순 wiring 자체는 대상이 아니다 — 아래 4-2 참고)

### 4-2. 테스트를 생략할 수 있는 대상

- props를 그대로 렌더링만 하는 presentational 컴포넌트
- `useQuery`/`useMutation`을 단순 호출만 하는 훅 (분기·가공 로직 없음)
- Page 컴포넌트 (하위 컴포넌트를 조합만 하는 경우)
- 스타일/레이아웃만 다루는 코드

### 4-3. 작성 규칙

- 테스트 파일은 대상 파일과 같은 디렉토리에 `*.test.ts(x)`로 둔다.
- 하나의 테스트는 하나의 핵심 동작만 검증한다.
- 컴포넌트 테스트는 구현 detail(내부 state, 함수 호출 여부)이 아니라 화면에 보이는 결과나 사용자 상호작용 결과를 검증한다.
- 현재 시각, 랜덤 값에 의존하는 테스트를 작성하지 않는다.

---

## 5. 코드 테스트로 남기지 않는 영역의 검증

핵심 로직이 아니어서 4장 기준에 해당하지 않는 화면 흐름(골든 패스, 주요 에러 상태)은 `docs/qa/` 시나리오 문서로 남기고 Playwright MCP로 확인한다.

- 시나리오 문서 작성 기준과 템플릿: `docs/qa/README.md` 참고
- 확인 시점: PR 생성 전 자체점검 (`frontend-review-rule.md` §검증)
- 확인 주체: 코드를 작성한 에이전트(Claude Code)가 직접 Playwright MCP로 조작하며 확인한다. 자동 실행되는 CI 게이트가 아니다.

---

## 6. 실행 명령

- `npm run lint`
- `npm test` (Vitest)

PR 생성 전에는 최소 lint와 단위 테스트를 실행한다.

---

## 7. 한 줄 요약

- 계산/분기/변환이 있는 순수 함수, validator, interceptor 로직만 선별적으로 Vitest로 테스트한다.
- presentational 컴포넌트, 단순 wiring 훅, Page 조합은 테스트를 생략할 수 있다.
- 생략한 화면 흐름은 `docs/qa/` 시나리오 문서로 남기고 Playwright MCP로 자체점검 때 확인한다.
