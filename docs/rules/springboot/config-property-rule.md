# Config Property Rule

## 1. 문서 목적

이 문서는 Java + Spring Boot 프로젝트에서 설정과 프로퍼티를 관리하는 기본 원칙을 정의한다.

---

## 2. 기본 원칙

설정은 코드에 흩뿌리지 않고, 구조화된 프로퍼티를 기준으로 관리하며, 의미 있는 설정 묶음은 타입 안전한 설정 클래스로 다룬다.

규칙:

- 설정 값은 `application.yml` 계열 파일에서 관리한다.
- 코드에서 문자열 키를 직접 반복 사용하지 않는다.
- 설정은 기능 단위 prefix 아래에 묶는다.
- 단순 문자열 주입보다 타입 안전한 설정 객체를 우선한다.
- 정책성 숫자와 시간 값은 코드 상수로 박아두기 전에 프로퍼티 후보인지 먼저 검토한다.

---

## 3. `application.yml` 구조 규칙

설정은 기능 단위로 계층화한다.

권장 예:

- `spring.datasource.*`
- `spring.flyway.*`
- `app.auth.*`
- `app.g2b.*` (나라장터 API 설정)
- `app.ai-worker.*`

규칙:

- 공통 프레임워크 설정은 `spring.*` 아래에 둔다.
- 애플리케이션 고유 설정은 `app.*` 아래에 둔다.
- 관련 없는 값을 같은 prefix 아래에 억지로 묶지 않는다.

---

## 4. prefix 네이밍 규칙

커스텀 설정 prefix는 기능 또는 도메인 기준으로 짓는다.

규칙:

- prefix는 짧고 의미 있게 유지한다.
- 도메인이나 기능 이름을 반영한다.
- 구현 세부나 클래스 이름을 prefix에 그대로 노출하지 않는다.
- 하나의 설정 클래스는 하나의 prefix만 담당하게 한다.

예:
- `app.auth`
- `app.g2b`
- `app.ai-worker`

---

## 5. `@ConfigurationProperties` 우선 원칙

여러 필드가 함께 움직이거나, 의미 있는 설정 묶음이 있으면 `@ConfigurationProperties`를 우선 사용한다.

적용 대상:

- 기능 단위 설정 묶음
- 중첩 구조가 있는 설정
- 숫자, 시간, boolean, 리스트 등 타입 변환이 필요한 설정
- 여러 클래스에서 재사용되는 설정

규칙:

- 설정은 가능한 한 타입 안전한 클래스로 바인딩한다.
- 관련 설정은 개별 `@Value`로 흩어 받지 않는다.

---

## 6. `@Value` 사용 제한

`@Value`는 예외적으로만 사용한다.

허용 범위:
- 정말 단일 값 하나만 필요한 경우
- 재사용되지 않는 단순 플래그

지양:
- 같은 prefix 값을 여러 개 주입하는 경우
- 여러 클래스에 같은 키를 반복 주입하는 경우
- 핵심 기능 설정을 문자열 키 기반으로 직접 받는 경우

즉, `@Value`는 편의용 예외이고, 기본 규칙은 `@ConfigurationProperties`다.

---

## 7. 타입 안전한 설정 클래스 규칙

- 필드는 의미 있는 타입으로 선언한다.
- 숫자, boolean, Duration, ZoneId, URL 등은 문자열로 뭉개지지 않게 한다.
- 설정 클래스는 가능하면 불변 필드를 사용한다 (`final` 또는 Lombok `@Value`).
- 설정 값을 런타임에 변경 가능한 상태 객체처럼 다루지 않는다.

---

## 8. 정책성 상수 분리 원칙

비즈니스 정책이나 운영 기준을 표현하는 숫자, 시간, 길이 값은 단순 구현 상수와 구분한다.

프로퍼티 후보 예:

- 토큰 만료 시간
- AI Worker 최대 Chunk 수
- 나라장터 API 조회 페이지 크기
- 분석 재시도 허용 횟수
- 스케줄러 실행 주기

규칙:

- 값이 바뀌면 기능 정책이나 운영 기준이 달라지는 경우 프로퍼티를 우선 검토한다.
- `180`, `3`, `20` 같은 매직 넘버가 시간, 횟수, 길이 의미를 가지면 코드에 직접 박아두지 않는다.

---

## 9. 민감정보 외부 주입 원칙

민감정보는 설정 파일 기본값에 하드코딩하지 않는다.

대상:
- 비밀번호
- 토큰 시크릿 (JWT_SECRET 등)
- API 키 (G2B_SERVICE_KEY, X-Internal-Api-Key 등)
- 외부 서비스 자격 증명
- AI API 키 (ANTHROPIC_API_KEY 등)

규칙:

- 민감정보는 환경 변수 또는 외부 설정으로 주입한다.
- 로컬 기본 설정 파일에 실제 운영 비밀값을 넣지 않는다.

---

## 10. 프로필별 설정 분리 원칙

환경에 따라 달라지는 설정은 프로필별로 분리한다.

규칙:

- 공통값은 기본 `application.yml`에 둔다.
- 환경별 차이는 `application-{profile}.yml`로 분리한다.
- 코드에서 프로필 문자열을 직접 비교해 분기하는 방식을 기본 규칙으로 삼지 않는다.

---

## 11. 금지 규칙

- 핵심 설정을 `@Value`로 흩어 주입하지 않는다.
- 민감정보를 코드나 기본 설정 파일에 하드코딩하지 않는다.
- 같은 설정 키를 여러 클래스에서 반복 문자열로 참조하지 않는다.
- 프로필 차이를 코드 분기로 우선 해결하지 않는다.
- 정책 의미를 가진 매직 넘버를 근거 없이 서비스 코드에 직접 하드코딩하지 않는다.

---

## 12. 한 줄 요약

- 설정은 `application.yml`에 구조화한다.
- 기능 단위 prefix와 `@ConfigurationProperties`를 우선 사용한다.
- `@Value`는 작은 예외에만 쓴다.
- 정책을 바꾸는 숫자와 시간 값은 프로퍼티 후보로 먼저 본다.
- 민감정보는 환경 변수로 외부 주입한다.
- 환경 차이는 프로필별 설정으로 관리하고 코드 분기는 최소화한다.
