# Logging Rule

## 1. 문서 목적

이 문서는 Java + Spring Boot 프로젝트에서 공통으로 적용할 수 있는 로깅 원칙을 정의한다.

---

## 2. 기본 원칙

로그는 많이 남기는 것보다, 필요한 정보를 일관되게 남기는 것을 우선한다.

규칙:

- 로그는 운영 판단과 장애 분석에 필요한 정보만 남긴다.
- 같은 사건을 여러 계층에서 반복 기록하지 않는다.
- 민감정보는 로그에 남기지 않는다.
- 정상 흐름 전체를 과도하게 로그로 덤프하지 않는다.

---

## 3. 로그 레벨 사용 기준

### 3-1. `ERROR`

시스템이 처리하지 못한 실패, 사용자 요청 실패, 데이터 불일치, 외부 시스템 오류 등 실제 운영 대응이 필요한 사건에 사용한다.

### 3-2. `WARN`

즉시 실패는 아니지만 비정상 상태이거나, 점검이나 후속 확인이 필요한 상황에 사용한다.

예:
- 재시도는 가능하지만 기대와 다른 결과가 발생한 경우
- 외부 시스템 지연, 부분 실패, fallback 적용 같은 경우

### 3-3. `INFO`

운영 관점에서 의미 있는 주요 이벤트만 기록한다.

예:
- 작업 시작과 종료
- 상태 전이 완료
- 배치 실행 결과 요약
- 중요한 비즈니스 이벤트 발생

### 3-4. `DEBUG`

개발 또는 문제 분석 시에만 필요한 내부 흐름 정보를 기록한다.

기본 운영 로그가 `DEBUG`에 의존하지 않게 한다.

---

## 4. 민감정보 로그 금지

다음 정보는 로그에 남기지 않는다.

- 비밀번호
- 토큰
- 시크릿
- API 키
- 인증 세션 식별자
- 개인정보 전체 값

규칙:

- 민감정보 원문을 그대로 출력하지 않는다.
- 필요하면 마스킹하거나 존재 여부만 남긴다.

---

## 5. 예외 로그 원칙

예외는 처리 책임이 있는 계층에서 한 번만 핵심 정보와 함께 기록한다.

규칙:

- 같은 예외를 여러 계층에서 중복으로 `ERROR` 로그하지 않는다.
- 예외를 다시 던질 뿐이면 상위 처리 계층에 로그 책임을 넘긴다.
- 사용자 오류와 시스템 오류를 같은 강도로 로그하지 않는다.

---

## 6. 정상 흐름 로그 최소화

정상적인 요청과 내부 흐름 전체를 `INFO`로 계속 기록하지 않는다.

지양:
- 메서드 진입/종료를 매번 `INFO`로 기록
- 단순 CRUD 성공 로그를 반복 기록
- 요청마다 상세 파라미터를 `INFO`로 출력

권장:
- 운영상 의미 있는 완료 이벤트만 `INFO`
- 상세 흐름은 필요 시 `DEBUG`
- 반복 처리 결과는 건별 로그보다 요약 로그

---

## 7. 요청/응답 로그 원칙

요청과 응답 전체를 기본값처럼 덤프하지 않는다.

규칙:

- 전체 헤더, 전체 바디, 전체 쿠키를 기본 로그로 남기지 않는다.
- 요청/응답 로그가 필요하면 메서드, 경로, 상태 코드, 처리 시간 같은 최소 정보부터 남긴다.
- 본문 로그가 꼭 필요하면 민감 필드 제거 또는 마스킹을 전제로 한다.

---

## 8. 비즈니스 이벤트 로그와 디버그 로그를 구분한다

- 비즈니스 이벤트 로그: 운영자가 사건 자체를 이해하는 데 필요한 로그 → `INFO` 또는 `WARN`
- 디버그 로그: 개발자가 내부 흐름을 추적하는 데 필요한 로그 → `DEBUG`

---

## 9. 운영 장애 분석을 위한 최소 기록 원칙

권장 항목:

- 사건 종류
- 대상 식별자 또는 내부 추적용 키
- 상태 코드 또는 결과 코드
- 주요 파라미터의 요약값
- 처리 시각
- 실패 원인 또는 예외 유형

규칙:

- 대상 식별자는 내부 추적에 필요한 최소 범위만 남긴다.
- 개인정보나 민감한 식별값은 원문 그대로 남기지 않는다.

---

## 10. 금지 규칙

- 민감정보를 로그에 그대로 남기지 않는다.
- 같은 예외를 여러 계층에서 중복 기록하지 않는다.
- 정상 흐름 전체를 `INFO` 로그로 도배하지 않는다.
- 요청/응답 전체를 기본값처럼 덤프하지 않는다.
- 운영 이벤트 로그와 디버그 로그를 섞어 쓰지 않는다.

---

## 11. 한 줄 요약

- 로그는 운영 분석에 필요한 최소 정보만 남긴다.
- 민감정보는 로그에 남기지 않는다.
- 예외는 책임 계층에서 한 번만 기록한다.
- 정상 흐름은 요약 중심으로 기록하고, 상세 흐름은 `DEBUG`로 내린다.
- 비즈니스 이벤트 로그와 디버그 로그를 구분한다.
