# Git Rule

## 1. 문서 목적

커밋 메시지 형식, 브랜치 규칙, 푸시 정책을 정의한다.

---

## 2. 커밋 메시지 형식

```
type(scope): 한글 요약

- 변경 상세 1
- 변경 상세 2
```

- 제목(subject): `type(scope): 한글 요약` 형식, 50자 이내
- 본문(body): 제목만으로 설명이 부족할 때만 작성, 없으면 생략
- 본문은 bullet point로 작성, 한글

---

## 3. 타입 정의

| 타입 | 사용 기준 |
|---|---|
| `feat` | 새 기능 추가 |
| `fix` | 버그 수정 |
| `refactor` | 기능 변경 없는 코드 구조 개선 |
| `test` | 테스트 추가/수정 |
| `docs` | 문서, Rule 파일, Task 파일 변경 |
| `chore` | 빌드 설정, 의존성, 환경 설정 변경 |
| `ci` | CI/CD 파이프라인 변경 |
| `style` | 포맷, 공백 등 동작 무관한 변경 |

---

## 4. 스코프 예시

스코프는 변경 대상 도메인 또는 모듈 이름을 사용한다.

| 스코프 | 대상 |
|---|---|
| `bid` | 입찰 공고 도메인 |
| `analysis` | AI 분석 도메인 |
| `auth` | 인증/인가 |
| `rule-engine` | 적합도 판단 엔진 |
| `scheduler` | 공고 수집 스케줄러 |
| `config` | 설정 파일, 환경 변수 |
| `infra` | Docker, docker-compose, 인프라 설정 |
| `docs` | 문서, Rule 파일 |
| `deps` | 의존성 추가/변경 |

스코프가 명확하지 않거나 여러 도메인에 걸쳐 있으면 생략한다.

---

## 5. 커밋 예시

```
feat(bid): 나라장터 공고 목록 조회 API 추가
```

```
fix(scheduler): 공고 수집 중복 저장 방지 로직 수정

- 동일 공고 번호 재수집 시 insert 대신 skip 처리
- G2B API 응답에 페이지 중복이 있는 경우 방어 코드 추가
```

```
docs(docs): springboot rule 파일 추가
```

```
chore(config): application.yml 환경 분리 구조 적용
```

---

## 6. 브랜치 규칙

| 브랜치 | 용도 |
|---|---|
| `main` | 운영 배포 기준 브랜치 |
| `feat/{epic}-{설명}` | 기능 개발 (예: `feat/epic1-bid-list`) |
| `fix/{설명}` | 버그 수정 (예: `fix/duplicate-bid-save`) |
| `chore/{설명}` | 설정, 의존성 (예: `chore/flyway-setup`) |

---

## 7. 금지 규칙

- 커밋 메시지를 영어로만 작성하지 않는다 — 요약과 본문은 한글로 작성한다
- 타입 없이 커밋하지 않는다
- 여러 독립적인 변경을 하나의 커밋에 묶지 않는다
- `main`에 직접 force push하지 않는다
- 민감정보(API 키, 비밀번호, .env 파일)를 커밋하지 않는다
