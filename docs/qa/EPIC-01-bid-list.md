# EPIC-01 공고 목록 시나리오

대상 화면: `/` (`BidListPage`)

---

## 시나리오 1: 골든 패스 — 목록 조회 및 검색/필터/정렬/페이지네이션

- 사전조건: 로그인된 상태(테스트 계정으로 로그인 완료). 공고 데이터가 21건 이상 존재하며, 그중 일부(예: 3건 정도)는 특정 키워드와 특정 지역에 동시에 매칭되도록 구성한다.
- 절차:
  1. `/` 접속
  2. 상단에 요약 바("전체 N건 / 오늘 신규 N건 / 오늘 마감 N건")가 보이는지 확인
  3. 검색창에 실제 존재하는 공고 제목의 일부 키워드를 입력하고 Enter (또는 "검색" 버튼 클릭)
  4. 지역 드롭다운에서 그 키워드와 함께 매칭되는 지역 선택
  5. 검색창과 지역 선택을 모두 초기화(검색어 삭제 후 Enter, 지역을 "전체 지역"으로 변경)해 21건 이상이 다시 보이는 상태로 되돌린다
  6. 정렬 버튼을 "최신순" → "마감일순" 순서로 각각 클릭
  7. "적합도순" 클릭
  8. 페이지네이션에서 2페이지로 이동
- 기대 결과:
  - 3번 이후: 키워드가 포함된 공고만 목록에 남고, 요약 바의 "전체 N건"이 검색 결과 건수로 갱신된다. "오늘 신규"/"오늘 마감" 건수는 검색·필터와 무관하게 항상 전체 공고 기준 값이므로 바뀌지 않는다 (의도된 동작)
  - 4번 이후: 선택한 지역과 키워드를 모두 만족하는 공고만 남는다. (참고: 필터를 좁힐수록 결과가 20건 이하로 줄어 페이지네이션이 아예 사라질 수 있다 — 그래서 6~8번은 필터를 초기화한 뒤 확인한다.)
  - 6번 각 클릭 시(최신순: `publishedAt desc`, 마감일순: `bidDeadline asc`) 목록 순서가 바뀌고, 선택된 정렬 버튼이 강조 표시(파란 배경)된다
  - 7번: `sort=SCORE` 요청이 정상적으로 전송되고 "적합도순" 버튼이 강조 표시된다. **단, 이 계정(회사 프로필)에 대해 계산된 매칭 결과(`bid_match_results`)가 없다면 `BidNoticeRepositoryImpl.orderBy()`가 `totalScore desc nullsLast` 다음으로 `publishedAt desc`를 타이브레이커로 쓰기 때문에, 화면상 순서가 "최신순"과 동일하게 보일 수 있다 — 이는 실패가 아니라 매칭 결과가 없을 때의 정상 폴백 동작이다.** 정렬이 실제 점수 기준으로 바뀌는 것까지 확인하려면 이 계정의 회사 프로필로 계산된, 서로 다른 `total_score` 값을 가진 매칭 결과가 최소 2건 이상 필요하다.
  - 8번 이후: 2페이지 공고 목록이 표시되고, 화면이 맨 위로 스크롤된다

## 시나리오 2: 비로그인 접근 시 로그인 페이지로 리다이렉트

- 사전조건: 로그아웃 상태 (쿠키/세션 없음)
- 절차:
  1. 로그인하지 않은 브라우저 세션에서 `/` 직접 접속
- 기대 결과: `/login`으로 리다이렉트되고 로그인 폼이 보인다

## 시나리오 3: 검색 결과 없음 (빈 상태)

- 사전조건: 로그인된 상태
- 절차:
  1. `/` 접속
  2. 검색창에 존재하지 않을 법한 키워드(예: `zzzqqqxxx없는공고`)를 입력하고 검색
- 기대 결과: "🔍 검색 결과가 없습니다." 안내 문구가 표시되고, 공고 카드나 페이지네이션은 보이지 않는다

## 시나리오 4: 목록 조회 API 실패

- 사전조건: 로그인된 상태에서, 백엔드가 응답하지 않거나 에러를 반환하도록 재현 (예: 백엔드 프로세스 중지 또는 Playwright MCP의 네트워크 요청 가로채기로 `/api/bids` 응답을 5xx로 강제)
- 절차:
  1. `/` 접속 (또는 이미 접속한 상태에서 검색 재실행)하여 목록 조회가 실패하도록 유도
  2. 에러 상태 UI 확인
  3. "다시 시도" 버튼 클릭
- 기대 결과:
  - 2번: 에러 메시지와 "다시 시도" 버튼이 화면 중앙에 표시된다 (공고 카드 없음). 단, 상단 요약 바("전체 N건" 등)는 React Query가 이전에 불러온 값을 그대로 들고 있어 화면에 남아있을 수 있다 — 이는 정상 동작이며 버그가 아니다.
  - 3번: API가 정상 응답하는 상태라면 목록이 다시 로드된다 (재현 환경을 원복한 뒤 확인)
