# QA 시나리오 문서

## 1. 목적

`docs/rules/frontend/testing-rule.md` 기준상 코드 테스트를 생략하는 화면 흐름(골든 패스, 주요 에러 상태)을 이 디렉토리의 시나리오 문서로 남긴다.
시나리오 문서는 자동화된 테스트가 아니라, Playwright MCP로 에이전트가 직접 브라우저를 조작해 확인하기 위한 절차서다.

---

## 2. 파일 구조

`docs/qa/EPIC-{번호}-{화면/기능명}.md` 형식으로 작성한다. (예: `docs/qa/EPIC-01-bid-list.md`)
하나의 파일에 해당 화면/기능의 시나리오를 여러 개 담을 수 있다.

```markdown
# EPIC-{번호} {화면/기능명} 시나리오

## 시나리오 1: {골든 패스 이름}
- 사전조건: {로그인 상태, 데이터 상태 등}
- 절차:
  1. {단계}
  2. {단계}
- 기대 결과: {화면에 보여야 하는 것}

## 시나리오 2: {에러 상태 이름}
- 사전조건: ...
- 절차: ...
- 기대 결과: ...
```

---

## 3. 작성 기준

- 화면당 최소 골든 패스 1개 + 주요 에러 상태(검증 실패, API 실패, 빈 상태 중 해당하는 것) 시나리오를 작성한다.
- 절차는 Playwright MCP로 그대로 따라할 수 있을 만큼 구체적으로 쓴다 (클릭 대상, 입력값 등).
- 코드 테스트로 이미 검증되는 로직(4장 기준의 계산/분기 등)은 시나리오에서 다시 검증하지 않는다. 화면 흐름과 렌더링 결과만 다룬다.

---

## 4. 확인 시점과 절차

- PR 생성 전 자체점검 단계에서, 코드를 작성한 에이전트가 해당 Task의 화면에 관련된 시나리오를 Playwright MCP로 직접 실행해 확인한다.
- 새 화면/기능을 추가하는 Task는 완료 전 이 디렉토리에 시나리오 문서를 추가하거나 기존 문서에 시나리오를 추가한다.
- 시나리오 확인 중 실패를 발견하면 코드를 수정하고 재확인한다. 시나리오 문서 자체를 실패에 맞춰 고치지 않는다.
- 화면 동작이 바뀌어 기존 시나리오의 절차/기대 결과가 더 이상 맞지 않게 되면, 해당 Task 안에서 시나리오 문서도 함께 갱신한다.
